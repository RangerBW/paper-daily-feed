# Agent 部署说明

[English](./agent-deployment.md) | [简体中文](./agent-deployment.zh-CN.md)

> 本文件是给 AI 编程 Agent 的补充指令，不重复面向用户的配置指南。

## 以项目文档为准

- 从头到尾阅读并执行 `@README.zh-CN.md`，重点遵循其中的 **快速开始**。该文件定义必填配置、可选功能和工作流。
- 只有当用户需要 `@README.zh-CN.md` 最小示例之外的配置时，才查阅 `@config/app.example.jsonc`。
- 只部署规范仓库：<https://github.com/nehSgnaiL/paper-daily-feed>。
- 如果本文件与 `@README.zh-CN.md` 不一致，停止并以 `@README.zh-CN.md` 为准。

## 与用户协作

- 部署全程使用用户的惯用语言沟通。优先根据对话判断；如果无法确定，只询问一次再继续。
- 让没有技术背景的用户也能轻松理解。沟通应友好并使用通俗的日常语言；对必要的专业术语作简短解释，并始终给出一个清晰的下一步操作。
- 使用当前已有的 GitHub 操作能力尽可能完成所有步骤。若已安装 `gh`，优先使用；除非工具需要，否则不要强制本地克隆。
- 每次只问一个问题，使用简单语言，并说明陌生值从哪里获取。先询问用户是否需要可选功能，再索取相应设置。
- 仅说明必须由用户手动完成的操作，例如 GitHub 授权或安全录入凭据。每个手动步骤完成后，继续自动执行。
- 修改前确认已登录的 GitHub 账号和目标 fork。尽量复用有效的现有 fork。部署期间不得修改规范仓库、推送 commit 或更改项目文件。

## 保护凭据

- 不要让用户在聊天中粘贴密码、令牌、授权码或 API key。
- 不得在命令参数、输出、日志、临时文件、配置变量或 shell 历史中暴露凭据。
- 使用安全的 secret 输入能力，或引导用户打开目标 fork 的 GitHub Actions Secrets 表单。等待用户确认，不要读取其输入值。
- `APP_CONFIG` 不得包含凭据。替换已有值前，先展示拟议的非敏感配置并获得确认。

## 完成部署

- 实际执行 `@README.zh-CN.md` 中的所有配置和工作流启用步骤，不要只描述操作方法。
- 运行文档指定的测试工作流并等待完成。如果失败，只检查不含密钥的日志，修正部署配置后重新运行。
- 不得削弱安全设置，也不得修改应用或工作流代码来强行通过测试。
- 仅当测试工作流成功后才结束。报告 fork 链接、成功运行链接、每日推送状态以及暂停推送的简单方法。不要重复任何凭据。
